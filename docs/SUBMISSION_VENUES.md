# Academic Submission Venues for DepegScope

## Primary Target Venues

### 1. Financial Cryptography and Data Security (FC)

**Website**: https://fc25.ifca.ai/ (check for current year)

**Why This Venue:**
- Premier venue for blockchain and cryptocurrency research
- Strong focus on economic and security aspects of cryptocurrencies
- High acceptance of DeFi security/risk papers
- Excellent visibility in the blockchain research community

**Paper Format:**
- Full papers: 15 pages (excluding references)
- Short papers: 8 pages
- Format: Springer LNCS style

**Typical Timeline:**
- Submission: September-October
- Notification: December
- Conference: February-March (usually Caribbean location)

**Review Criteria:**
- Technical soundness
- Novelty and significance
- Relevance to financial cryptography
- Presentation quality

**Tips for FC:**
- Emphasize security implications of systemic risk
- Include economic analysis
- Provide reproducible experiments
- Consider the "systemization of knowledge" (SoK) track if more survey-oriented

---

### 2. Internet Measurement Conference (IMC)

**Website**: https://conferences.sigcomm.org/imc/

**Why This Venue:**
- Top venue for empirical internet/network measurement
- Accepts blockchain measurement studies
- Strong emphasis on methodology and data quality
- High impact factor in networking community

**Paper Format:**
- Full papers: 14 pages (ACM format)
- Short papers: 6 pages

**Typical Timeline:**
- Submission: May
- Notification: August
- Conference: October-November

**Review Criteria:**
- Measurement methodology rigor
- Dataset quality and availability
- Empirical contributions
- Reproducibility

**Tips for IMC:**
- Focus on the measurement aspects (data collection, graph analysis)
- Provide detailed methodology section
- Make datasets available
- Include statistical rigor in analysis

---

### 3. ACM Conference on Computer and Communications Security (CCS)

**Website**: https://www.sigsac.org/ccs/

**Why This Venue:**
- Top-tier security conference (CORE A*)
- Accepts blockchain security research
- High visibility and prestige
- Strong review process

**Paper Format:**
- Full papers: 12 pages (double-column ACM format)

**Typical Timeline:**
- Two submission deadlines per year (typically January and May)
- Notification: ~3 months after submission
- Conference: November

**Review Criteria:**
- Security relevance and impact
- Technical depth
- Novelty
- Practical implications

**Tips for CCS:**
- Frame as a security problem (systemic risk = security vulnerability)
- Include threat model
- Discuss attack scenarios and defenses
- Emphasize practical impact

## Journal Options (For Extended Version)

### 1. IEEE Transactions on Dependable and Secure Computing (TDSC)

- Impact Factor: ~7.0
- Good for extended security analysis
- Longer format allows more detail

### 2. ACM Transactions on Privacy and Security (TOPS)

- Impact Factor: ~3.5
- Accepts blockchain security
- Good reputation in security community

### 3. Journal of Financial Economics / Review of Financial Studies

- Very high prestige
- For purely economic/finance angle
- Requires strong empirical finance methodology

### 4. Frontiers in Blockchain

- Open access
- Fast review process
- Good for blockchain-specific work

## Submission Strategy

### Recommended Approach

1. **First Submission: FC or IMC**
   - FC if emphasizing security/economics
   - IMC if emphasizing measurement methodology

2. **If Rejected: Revise and Submit to CCS or AFT**
   - Incorporate reviewer feedback
   - Strengthen weak areas identified

3. **After Conference: Extended Journal Version**
   - Add additional experiments
   - Deeper analysis
   - Submit to TDSC or TOPS

## Preparation Checklist

### Before Submission

- [ ] Paper follows venue formatting guidelines exactly
- [ ] All figures are high resolution and readable in print
- [ ] Code is cleaned and documented
- [ ] GitHub repository is public (or will be upon acceptance)
- [ ] Datasets are prepared for release
- [ ] Supplementary materials are ready
- [ ] All co-authors have reviewed and approved
- [ ] Conflict of interest declarations are prepared

### Paper Quality Checks

- [ ] Abstract is within word limit and compelling
- [ ] Introduction clearly states contributions
- [ ] Related work is comprehensive and fair
- [ ] Methodology is reproducible from paper alone
- [ ] Results include statistical significance
- [ ] Limitations are honestly discussed
- [ ] References are complete and properly formatted

### Artifact Preparation

- [ ] README with setup instructions
- [ ] Requirements.txt or environment.yaml
- [ ] Sample data or instructions to obtain data
- [ ] Scripts to reproduce key results
- [ ] Expected output examples

## Common Rejection Reasons (and How to Avoid)

1. **"Incremental contribution"**
   - Ensure novelty is clearly articulated
   - Compare explicitly to prior work
   - Quantify improvement over baselines

2. **"Methodology concerns"**
   - Provide detailed methodology section
   - Include validation/ablation studies
   - Address potential confounds

3. **"Limited evaluation"**
   - Include multiple case studies
   - Add sensitivity analysis
   - Provide statistical significance tests

4. **"Not generalizable"**
   - Test across different scenarios
   - Discuss applicability to other contexts
   - Avoid overfitting to specific events

5. **"Presentation issues"**
   - Have multiple people proofread
   - Ensure figures are self-explanatory
   - Follow formatting exactly
