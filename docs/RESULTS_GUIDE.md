# Documenting and Presenting Results

This guide explains how to run DepegScope, interpret the outputs, and present findings for academic publication.

---

## 1. Running the Complete Analysis Pipeline

### 1.1 Quick Start

```bash
# Activate virtual environment
source venv/bin/activate

# Step 1: Collect data
python scripts/collect_data.py --days 365 --top-protocols 100

# Step 2: Build dependency graph
python scripts/build_graph.py --min-tvl 1000000 --export-graph

# Step 3: Run simulations
python scripts/run_simulation.py --scenario usdc_svb --monte-carlo 1000

# Step 4: Generate report
python scripts/generate_report.py --format all --generate-plots
```

### 1.2 Expected Output Files

## 3. Figures for Publication

### 3.1 Required Figures

1. **System Architecture** (Figure 1)
   - Create in Figma/Excalidraw/draw.io
   - Show data flow: Collection → Graph → Simulation → Visualization

2. **Dependency Network** (Figure 2)
   - Generated by `network_plots.py`
   - Color nodes by type (stablecoin/protocol)
   - Size by market cap/TVL
   - Edge thickness by exposure weight

3. **Centrality Distribution** (Figure 3)
   - Histogram or violin plot
   - Compare stablecoins vs protocols
   - Highlight outliers (systemic risks)

4. **Cascade Timeline** (Figure 4)
   - X-axis: simulation steps
   - Y-axis: number of depegged coins / distressed protocols
   - Multiple lines for different scenarios

5. **Historical Validation** (Figure 5)
   - Side-by-side comparison
   - Predicted vs. actual protocol impact
   - Include error bars

6. **Risk Heatmap** (Figure 6)
   - Protocols vs. stablecoins
   - Color intensity = exposure percentage
   - Cluster by category

7. **Monte Carlo Distribution** (Figure 7)
   - Loss distribution histogram
   - Mark VaR and CVaR lines
   - Compare scenarios

### 3.2 Figure Specifications

For most academic venues:
- **Resolution**: 300 DPI minimum
- **Format**: PDF or EPS (vector preferred)
- **Colors**: Use colorblind-friendly palette
- **Font**: Match paper font (often Times/Computer Modern)
- **Size**: Single column (~3.5") or double column (~7")

## 5. Statistical Analysis

### 5.1 Significance Testing

For comparing scenarios:
```python
from scipy import stats

# Two-sample t-test
t_stat, p_value = stats.ttest_ind(usdt_losses, usdc_losses)

# Mann-Whitney U (non-parametric)
u_stat, p_value = stats.mannwhitneyu(usdt_losses, usdc_losses)

# Report: "USDT depeg scenarios resulted in significantly higher
# losses than USDC (p < 0.001, Mann-Whitney U test)"
```

### 5.2 Confidence Intervals

```python
import numpy as np

# Bootstrap confidence interval
n_bootstrap = 10000
means = []
for _ in range(n_bootstrap):
    sample = np.random.choice(losses, size=len(losses), replace=True)
    means.append(np.mean(sample))

ci_95 = np.percentile(means, [2.5, 97.5])
# Report: "Mean TVL loss: $23.4B (95% CI: $21.2B - $25.6B)"
```

### 5.3 Effect Sizes

```python
# Cohen's d for comparing means
def cohens_d(group1, group2):
    n1, n2 = len(group1), len(group2)
    var1, var2 = np.var(group1), np.var(group2)
    pooled_std = np.sqrt(((n1-1)*var1 + (n2-1)*var2) / (n1+n2-2))
    return (np.mean(group1) - np.mean(group2)) / pooled_std

d = cohens_d(usdt_losses, usdc_losses)
# Report: "Large effect size (Cohen's d = 0.85)"
```

## 6. Presenting Results in the Paper

### 6.1 Results Section Structure

```markdown
## 6. Evaluation

### 6.1 Dependency Graph Analysis
[Graph statistics, centrality analysis, chokepoint identification]

### 6.2 Historical Validation
[Case studies with accuracy metrics]

### 6.3 Scenario Analysis
[Monte Carlo results, sensitivity analysis]

### 6.4 Early Warning System Performance
[Indicator evaluation, lead time analysis]
```

### 6.2 Writing Style

**Do:**
- Lead with the most important finding
- Provide specific numbers with units
- Reference figures/tables
- Explain implications

**Don't:**
- Bury key findings in text
- Use vague language ("many", "significant" without numbers)
- Over-interpret results
- Hide negative results

**Example:**
> "Our analysis reveals that USDT represents the most significant systemic risk in the DeFi ecosystem. A 10% USDT depeg scenario results in a mean TVL loss of $23.4B (95% CI: $21.2B-$25.6B), affecting 89 of the top 132 protocols (Figure 5). This represents 51.4% of the total analyzed TVL, compared to 39.9% for USDC and 17.8% for DAI (Table 4)."

### 6.3 Visualizing Uncertainty

Always show uncertainty in results:
- Error bars on bar charts
- Confidence bands on time series
- Box plots instead of bar charts when appropriate
- Report confidence intervals in text

## 7. Supplementary Materials

### 7.1 What to Include

- Extended methodology details
- Additional figures (e.g., all 24 stablecoin analyses)
- Full simulation parameter tables
- Sensitivity analysis results
- Code availability statement

### 7.2 Artifact Submission

Many venues (especially ACM) encourage artifact evaluation:

1. **Functional**: Code runs and produces claimed results
2. **Reusable**: Well-documented, can be extended
3. **Available**: Publicly accessible (e.g., GitHub, Zenodo)

Prepare:
- Clean GitHub repository
- README with step-by-step instructions
- Sample data or data collection scripts
- Expected output examples
- Docker container for reproducibility

## 8. Common Pitfalls to Avoid

1. **Cherry-picking results**: Report all scenarios, not just dramatic ones
2. **Overfitting to historical events**: Test on held-out events
3. **Ignoring uncertainty**: Always report confidence intervals
4. **Causation claims**: Network analysis shows correlation/dependency, not causation
5. **Overconfident predictions**: Acknowledge model limitations
6. **Stale data**: Clearly state data collection dates
7. **Missing baselines**: Compare to simple alternatives
